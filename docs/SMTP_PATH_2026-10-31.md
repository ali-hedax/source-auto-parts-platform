# SMTP path diagnosis and repair — 2026-10-31

## Evidence

API and worker have matching SMTP configuration, SMTP credentials and encryption
key (compared in memory; no values logged). Both are running, with no restarts.
Redis has no waiting, active, delayed or failed event jobs and is not paused.
All ten historical email outbox rows are DONE; this means handled, not delivered.
Two invitation messages failed after five attempts with
`SMTP_TEMPORARY ETIMEDOUT`. Worker logs contain retries without authentication,
certificate, renderer or Redis failures. The requested invitation is still
active, unaccepted, unrevoked and outside the trash. Its final email is FAILED,
has no sent timestamp and its encrypted send token has been cleared by design.

The configured destination `mail.parsgate.online:587` resolves to IPv4, accepts
TCP and sends greeting 220. STARTTLS verification times out before authenticated
SMTP. Port 465 also times out and was not adopted. Two scoped TCP SYN MSS rules
(1260 bytes, OUTPUT and FORWARD, destination SMTP IPv4 and TCP port 587 only)
resolve this: the existing credentials successfully authenticate with TLS 1.2+
and certificate validation from both the actual API and actual worker containers.
No password, hostname, TLS mode, port, environment file or container was changed.
This before/after result establishes packet sizing on the SMTP network path as
the cause of the observed TLS timeout; it does not locate the upstream network
device dropping packets.

## Persistence and rollback

Production has the equivalent of `infra/network/hedax-mail-path-mss.sh` installed
at `/usr/local/sbin/hedax-mail-path-mss`, root-owned mode 700, with the adjacent
systemd unit installed under `/etc/systemd/system/`. The unit is enabled and
active. Script syntax and systemd validation passed. A reboot was not performed.
The existing unrelated MTU/MSS rules were retained.

The hostname is resolved when the service runs. If the SMTP destination or its
DNS changes, re-evaluate the path and rerun/revise this narrowly scoped rule;
do not disable TLS certificate validation or switch to clear-text SMTP.

To roll back this repair, disable/stop `hedax-mail-path-mss.service`, then remove
only the two `hedax-mail-mss-20261031` rules with their recorded destination,
port, SYN mask and MSS value from OUTPUT and FORWARD. The private receipt is
`/opt/hedax-release-candidates/parts-mail-20261031/mail-mss-added.json`.
Do not flush the mangle table or delete existing site/storage rules.

## Test limits

No SMTP DATA command, test email or invitation resend was issued. Authentication
success is not SMTP acceptance of a message or inbox delivery. The failed
message cannot be retried with its old encrypted token because final failure
clears that token. Use the existing staff invitation resend flow to issue a fresh
link and queue a fresh message; it replaces the old invitation token. Verify the
new row reaches SENT with an SMTP 250 response, then verify the actual inbox
(including spam). Do not describe the prior failed message as sent.

Existing isolated tests passed: SMTP/template unit 4/4; invitation integration
