# Iran-market vehicle dataset (home-page vehicle finder)

`iran-market.v1.json` is the reviewed list behind the finder's steps
(group → vehicle → model/trim → year). It is generated by `build-iran-market.py`
so every record and every exclusion can be reviewed and regenerated:

```sh
py build-iran-market.py          # rewrites iran-market.v1.json
```

Coverage, sources and open items for the owner: [COVERAGE.md](COVERAGE.md).

## Shape

| field | meaning |
| --- | --- |
| `sources.<ref>` | `url`, `title`, `publisher`, `kind` (`official` / `secondary`), `market`, `checkedOn` (Gregorian ISO date) |
| `vehicles[].key` | stable data key (`ikco.samand`); the import is idempotent on it |
| `vehicles[].groups` | finder groups: `IKCO`, `SAIPA`, `TOYOTA`, `HYUNDAI` (several when two groups made or supplied it) |
| `vehicles[].make` | the original make (پژو، رنو …), never the group; `null` when no cited source states it |
| `vehicles[].existing.slug` | reuse this existing catalogue row (id, slug, name and product links are kept) |
| `vehicles[].status` | `official`, `secondary` or `needs_review` (reported, not imported) |
| `models[].supply` / `supplier` | `domestic` / `assembled` / `imported` and the company in Iran, only when a source says so |
| `models[].years` | `{from, to, calendar: jalali / gregorian, source}`; imported only when `source` is official; never converted between calendars |
| `equivalences[]` | a reviewed older row (`legacy.vehicleSlug` / `modelSlug`) whose product links also count for this vehicle; `uncertain` ones are reported, not imported |
| `notes[]` | what was looked at and deliberately left out, and why |

Every vehicle, model and year cites `sources[].ref` with the claim it supports.

## Import

```sh
pnpm --filter @hedax/api build
node apps/api/dist/database/import-vehicles.js --file database/datasets/vehicles/iran-market.v1.json --report <dir>          # dry run
node apps/api/dist/database/import-vehicles.js --file database/datasets/vehicles/iran-market.v1.json --report <dir> --apply  # write
```

- The dry run writes `report.json` and `report.md` (new / matched / unchanged / duplicate / conflict / uncertain) and changes nothing.
- An existing row is reused only when the dataset names it (`existing.slug`). A same-name row that is not named is a conflict, never a silent merge.
- Existing ids, slugs, names and product links are never changed; nothing is deleted or renamed; vehicles are never linked to products; prices and stock are not touched.
- Names are compared with the shared Persian normalization (`vehicleKey`).
- A second `--apply` creates nothing (`new: 0`).
- With `APP_ENV=production` the importer refuses to write unless `HEDAX_VEHICLE_IMPORT_PRODUCTION=approved` is set — an explicit owner decision.
